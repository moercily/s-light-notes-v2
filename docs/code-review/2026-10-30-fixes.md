## F2 复审补修：保存与恢复共用锁

2026-10-30 复审发现原先只有删除/恢复经过队列与 Web Lock，普通 `fsaSaveNote` 未参与。标签页 A 恢复时确认 `a.md` 空闲，标签页 B 随后成功新建同名笔记，A 继续写入后仍会覆盖 B 的内容。该问题发生在同源应用内部，不能归入外部程序并发限制。

本次将全部 FSA 写入入口纳入同一队列及 Web Lock：新建名称分配、写入与关闭，以及移动的源读取、目标分配、复制与源删除都在各自的完整临界区中执行。沿用原锁名 `s-light-notes-fsa-move`，使新版保存也能协调原有移动操作；旧页面中未加锁的保存仍须重新加载页面后才受保护。保存排队前捕获目录句柄，名称分配也使用该句柄，防止等待期间切换目录后向原目录分配重名。写入失败尝试 abort，错误继续返回调用方，后续队列操作可继续执行。Service Worker 缓存更新为 `0.1.1-review-fixes-2`。

先只添加交错回归，运行 `npm run test:container -- review-regressions`，确认修复前失败：活动目录只剩旧 `a.md`，第二份新正文丢失。随后修改实现并运行：

```sh
npm run test:container -- review-regressions desktop-storage reliability native-shell
```

隔离 ARM64 QEMU/Colima、无网络且无宿主目录挂载的容器内，4 个套件全部通过，套件执行合计约 0.90 秒。新增 9 个场景包括：模拟 Web Locks 的双页面与无 Web Locks 的单窗口分别覆盖恢复先行、新建先行、两次并发新建（6 个）；等待期间切换文件夹（1 个）；更新成功/失败后另一页面移入回收站（2 个）。执行真实存储函数，以内存目录句柄、提交时更新正文的可写流及按锁名排队的锁管理器模拟平台边界；没有运行真实浏览器 FSA 或原生安装版验收。本轮未重跑前述 Rust 和真实引擎验证。`git diff --check` 通过；测试容器已删除，本轮启动的 `slight-qa` 已停止，保留镜像缓存。
