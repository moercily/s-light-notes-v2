## P1：可能造成数据丢失或突破原生边界

### F7：桌面通用同步代理绕过配置确认和固定目录限制

- 位置：`src-tauri/src/desktop.rs:1057-1068`，`src-tauri/src/desktop.rs:2327-2334`；授权入口 `src-tauri/capabilities/default.json:13`。
- 前提：桌面 main WebView 获准调用 `syncthing_proxy_request`，应用托管引擎运行中。无须知道原生持有的 API Key。
- 触发：调用该 IPC，传入 `method: "POST"`、`path: "/rest/config/folders"` 和含其他 folder ID/path 的 JSON body；无须调用 preview/confirm。类似地可访问配置设备等 POST 路径。
- 预期：配置写入经过 token 确认、实时复查、固定目录校验和回读/回退；前端不能任意提供文件路径或取得原始私密配置。
- 实际：命令只限制 GET/POST，路径校验只排除非 `/` 开头、`://` 和 `..`；Rust 自动附加原生凭据并原样返回响应。普通 POST 配置路径可直达引擎，绕过专用命令的完整约束。
- 影响：main 内运行的脚本能够越过原本声称的原生配置边界，建立其他目录绑定/设备配置；是否进一步造成数据外传取决于后续共享配置。本次未证明外部笔记可执行脚本或远程攻击入口，不能据此声称存在远程代码执行。
- 证据：源码/ACL 静态确认；隔离 v2.1.2 原生引擎中 POST `/rest/config/folders` 成功创建 `review-no-confirmation`，GET 回读确认。GET `/rest/config/gui` 还返回原始 GUI 配置，包含磁盘配置的 API Key；该值在本次环境中不同于环境变量覆盖的有效密钥，不能声称已泄露有效运行密钥。
- 建议：改用按操作命名的命令，或在原生层严格允许所需只读端点和固定 folder 扫描操作；拒绝全部通用配置读写，返回经过字段筛选的数据。补测即使拥有 main ACL，也不能直接代理 config POST/GET。
- 未验证：本次未启动 Tauri 安装版执行 IPC；协议证据和原生命令/ACL 调用链分别验证。

### F1：Web 保存期间的新输入被旧保存标记为已保存，切换后丢失

- 位置：`app/js/editor.js:95-99`。
- 前提：Web 主界面，IndexedDB 或 FSA；这里不经过桌面专用保存队列，也不经过移动端保存队列。
- 步骤：编辑内容 first → 保存写入尚未返回 → 输入 second → first 写入返回 → 在下一次自动保存前点击新建或另一笔记。
- 预期：second 仍为 dirty，导航先保存或保留它。
- 实际：旧保存无条件设置 `AppState.isDirty = false`，导航直接清空/替换编辑器，磁盘仍是 first。后续自动保存看到 clean 也不会补救。
- 影响：新增输入永久丢失；慢文件操作、手动保存与自动保存交叠时风险更明显。
- 原因：缺少按编辑会话和快照核对的保存结果处理，且没有串行队列。
- 证据：容器 F1，控制保存 Promise 返回顺序，确认磁盘 first、编辑器 second、dirty=false；调用真实 `onNewNote()` 后 second 消失。
- 建议：将 Web 保存纳入同等队列；保存完成只清除与快照一致的 dirty；新 ID 与结果只应用到对应编辑会话。保留“写入中输入后立即导航”回归。
- 未验证：真实浏览器 IndexedDB/FSA 时延与交互；本次只替换存储边界，执行真实保存和导航函数。

### F2：FSA 回收站同名恢复覆盖现有笔记，重复删除也覆盖旧回收副本

- 位置：`app/js/storage.js:634-641`、`app/js/storage.js:662-669`。
- 前提：Web FSA 文件夹模式。
- 步骤：删除 old 内容的 a.md → 新建 new 内容的 a.md → 从回收站恢复旧 a.md。另一个触发是再次删除同名 a.md。
- 预期：以编号副本等方式保留两份内容，与指南的数据保全约束一致。
- 实际：恢复使用固定文件名及 `{create:true}` 获取可写句柄，直接覆写 new，随后删除回收站 old；重复删除同样覆写 `.trash/a.md`。
- 影响：其中一份内容丢失，没有冲突提示。工作区的 Rust 回收站修复只覆盖桌面存储，没有覆盖 FSA。
- 证据：容器 F2，执行真实 FSA 函数，以内存目录句柄模拟平台边界；恢复后活动文件只有 old、回收站为空。重复删除的同一写入路径静态确认。
- 建议：两个方向均生成不冲突的目标名，明确 FSA 的并发限制，复制成功后再删除源；回归覆盖重复删除、同名恢复和复制失败保留源。
- 未验证：真实 FSA 文件系统调用及跨进程竞态。

### F6：Web/PWA 同名导入静默覆盖 IndexedDB 笔记

- 位置：`app/js/storage.js:585-590`；更新语义在 `app/js/storage.js:279-321`。
- 前提：IndexedDB 已有 id=a 的笔记；Web 主窗口或移动 PWA 执行导入。
- 步骤：导入内容不同的 a.md。
- 预期：保留原笔记、创建副本，或至少明确提示覆盖并征求确认。
- 实际：文件名直接作为已有 id 交给 `idbSaveNote`，走 `put` 更新；成功计数为 1，无冲突/覆盖提示。若同 id 位于回收站，重建 record 还会去掉 archived 字段。
- 影响：原正文被替换，没有导入回退或原版副本。桌面与 Android 的创建副本分支不受此问题影响。
- 证据：容器 F6，执行真实导入和 `idbSaveNote`，以模拟异步 get/put 的存储边界记录结果；笔记总数仍为 1，original 变为 imported。回收站字段行为静态确认。
- 建议：导入走独立的唯一 ID 创建逻辑，保留文件名作为建议名称；必要时用事务保证创建不覆盖。回归覆盖活动与回收站同名项。
- 未验证：真实 IndexedDB 事务和文件选择器。

## P2：功能与导航状态错误

### F3：从只读冲突笔记新建后，编辑器仍只读

- 位置：`app/js/sidebar.js:185-195`；`clearEditor()` 在 `app/js/editor.js:49`，不会恢复 contentEditable。
- 前提：主界面已打开冲突笔记，编辑器 `contentEditable=false`。
- 步骤：点击新建或按 Ctrl/Cmd+N。
- 预期：空白草稿立即可输入。
- 实际：状态 `_currentNoteReadOnly` 已清除，但 DOM 仍 `contentEditable=false`。Web 可持续到下一次列表刷新/选择；桌面通常在下一次可见窗口轮询刷新后恢复，约两秒。
- 证据：容器 F3，真实 `onNewNote()` 返回后，状态已可写而编辑器属性仍为 false。
- 建议：新建完成后调用统一编辑权限更新逻辑，兼顾退出冻结；增加 conflict → new 集成回归。
- 未验证：安装版键盘、焦点和实际轮询等待时间。

### F4：Android 从后台返回列表或设置页，会跳回上次的笔记

- 位置：`app/js/mobile.js:430-434`。
- 前提：打开一条已保存笔记，再返回列表/设置；`currentNoteId` 仍保留。
- 步骤：切后台，再回到应用。
- 预期：保留用户离开前的页面，后台刷新数据即可。
- 实际：visibility 处理只检查 currentNoteId 和 dirty，不检查 `_view`，调用 `openMobileNote()`；该函数调用 `showMobileView('editor')` 并增加 history 项。sync 页有单独处理，其余页没有。
- 影响：恢复应用时发生意外导航，设置操作被中断，返回历史增加不必要条目。
- 证据：容器 F4，visible + list + clean current note，处理后 `_view` 从 list 变成 editor。
- 建议：仅在编辑页更新当前笔记，其他页只刷新相关数据，读取与导航解耦。回归覆盖 list/settings/sync/editor 四种恢复位置。
- 未验证：Android 真正前后台生命周期；本次验证 visibility 控制器。

### F5：移动端系统返回未使挂起读取失效，迟到结果将用户带回编辑页

- 位置：`app/js/mobile.js:443-453`；读取后的有效性检查在 `app/js/mobile.js:544-553`。
- 前提：Android/移动 PWA 正在读取笔记，例如前台恢复触发当前笔记刷新，读取尚未返回。
- 步骤：系统返回触发 popstate 到列表 → 旧 readNote 结果返回。
- 预期：停留列表，丢弃旧导航的读取结果。
- 实际：popstate 未递增 mobileNavigation，旧结果仍通过序号检查，再次调用 showMobileView('editor')。
- 影响：返回操作被撤销，旧导航覆盖新页面状态。
- 证据：容器 F5，以可控 Promise 挂起真实 `openMobileNote()`，派发 popstate，确认先到 list，释放读取后又到 editor。
- 建议：每次离开编辑页或系统导航都使读取会话失效，异步返回同时检查导航和预期视图。回归覆盖硬件返回、手势返回和延迟读取。
- 未验证：真实 Android 返回事件到 WebView history 的投递。
